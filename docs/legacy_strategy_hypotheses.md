# 旧交易逻辑消化与处置

更新时间：2026-08-22

旧 v4.1 的价值是提供研究假设和执行经验，不是提供已经证明的 alpha。现有逻辑已逐项拆解如下。

| 旧逻辑 | 原意 | 当前处置 |
|---|---|---|
| 按币种/模式设置预测阈值 | 过滤微小波动 | 保留为可训练/可校准阈值假设；禁止用常数直接授权真钱 |
| 预测方向 + BTC 锚点/趋势条件 | 避免山寨币逆大盘 | 保留为 cross-asset/regime 因子候选；必须在 PIT OOS 消融中证明增益 |
| BTC/ETH 100x、其他 75x，目标杠杆收益 31% | 把小幅预测转换成高杠杆收益目标 | 只保留为 Brain 标签/显示历史兼容；新操作票默认 leverage cap 3x，绝不把模型目标当账户杠杆 |
| 0.6% 账户分配/固定比例开仓 | 控制单笔规模 | 改为止损风险预算、目标暴露、名义上限、可用保证金和组合容量取最小值 |
| 多档 take-profit | 分批兑现 | 保留为保护模板；当前操作票以费用后 edge 和批准 risk/reward 生成，成交后创建确定性 reduce-only 子单 |
| 动态 stop-loss / trailing | 盈利保护与尾部控制 | 保留思路；入场单原子附带 Mark Price 止损，trailing 只有测试网证据后才能启用 |
| 直接读取预测 JSON/阈值并下单 | 低延迟、实现简单 | 已废止；预测只能发布版本化 Forecast 和 OperationTicket，交易端不解释预测内部字段 |
| REST 返回后按订单成功处理 | 简化状态 | 已废止；REST 只算异步受理，必须由私有 order/execution 流和 execId 确认 |

必须单独验证的假设包括：阈值随币种波动率是否稳定、BTC 锚点在风险切换期是否反向、爆仓热区是否只在特定流动性 regime 有效、分批止盈是否在费用后优于单一退出、预测 horizon 与最长持仓是否一致、资金费率/价差是否吞噬高换手 edge。

旧数据库和旧脚本保留作审计存档，不再是活跃执行入口。当前 `bot_threshold_super_v4_1.py` 只启动版本化执行服务。
