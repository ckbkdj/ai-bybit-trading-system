# 主网上线门禁（默认 NO-GO）

更新时间：2026-08-22

本文件不是主网授权。只有全部项目有可审计证据、用户明确批准并在预定窗口内操作，才能把 `BYBIT_TRADING_MODE` 改为 `live`。本次实现没有启用主网。

## 凭证与网络

- [ ] 源码/历史日志中出现过的 Bybit、Webhook、控制面凭证已全部撤销并重建。
- [ ] 新 key 仅有交易所需最小权限，不开放提现，绑定固定内网出口 IP。
- [ ] 控制面使用内网 TLS 和有效 CA；token 已轮换并通过安全方式注入。
- [ ] 系统时间同步，实际漂移持续低于配置阈值。

## 账户与交易所

- [ ] `BYBIT_POSITION_MODE` 与目标账户实际 hedge/one-way 完全一致。
- [ ] 统一账户、保证金币种、杠杆和最大订单限制已核对。
- [ ] testnet 已证明 OPEN/REDUCE/CLOSE/CANCEL/REPLACE。
- [ ] testnet 已证明部分成交、重复事件、cancel/fill、断线重连和重启恢复。
- [ ] testnet 已证明入场附带止损、止盈子单和退出订单 `reduceOnly`。

## 策略与风险

- [ ] shadow 至少覆盖预定的完整市场周期，并完成新旧逻辑差异报告。
- [ ] 每个启用因子组有严格 PIT 的样本外消融证据；无改善的组未启用。
- [ ] 手续费、资金费率、价差、滑点、部分成交和延迟已纳入回测。
- [ ] 单币种、低杠杆、低仓位、每日次数、日亏损和相关暴露上限已书面批准。
- [ ] kill switch 已做人工演练，值班人知道如何检查仓位和未完成订单。

## 运行与恢复

- [ ] 控制面、执行库和模型已做可恢复备份；恢复演练成功。
- [ ] 监控覆盖 WebSocket、票据积压、回执积压、时钟、源中断、保证金和异常订单。
- [ ] 网络分区时不会盲目重发；按 orderLinkId/execId 对账流程已演练。
- [ ] 上线窗口、回退负责人、停机条件和人工联系方式已确认。

## 最终人工动作

- [ ] 用户明确批准本次主网窗口和限额。
- [ ] 先保持 `BYBIT_ENABLE_LIVE=false` 完成最后一次配置审查。
- [ ] 在窗口内同时设置 `BYBIT_TRADING_MODE=live` 与 `BYBIT_ENABLE_LIVE=true`。
- [ ] 首笔仅使用批准的最小规模；确认订单、成交、保护和回执后再继续。

任何一项失败：立即保持或恢复 `shadow`，必要时开启 kill switch。不要通过改数据库、跳过 WebSocket 或放宽数据质量来“临时上线”。
